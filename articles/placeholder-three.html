This is the long one. It runs past a screen so the panel can show what reading a real article feels like: the panel grows with the text, the page scrolls, and the index stays in view beside it on a wide screen.

Why the panel grows

A box that scrolls inside a page that scrolls is hard to read in. The wheel moves one or the other depending on where the cursor sits, keyboard users have to find the inner box before they can scroll it, and a phone gives a long article almost no room. So the panel takes the article's full height and the page does the scrolling.

The trade-off is that a long article pushes the projects and the operator further down the page. The nav keys in the top bar get you there in one press.

How an article gets here

Each article is a Markdown file in content/articles/. A build script turns it into its own page and adds it to the home page's list, newest first. When the page loads, a small script fetches the first one, takes its article element and puts it in the panel. Picking another one does the same and sets the address to the article's name, so the back button and shared links work.

  1. Write the new article as a Markdown file in content/articles/.
  2. Run uv run build.py and commit what it wrote.

Without JavaScript

Every item in the list is a normal link to the article's own page, so nothing breaks. The panel just shows a link to the newest article instead of the article itself.

A third-level heading

Headings inside an article step down a level in the panel, so the page keeps one outline: the section heading, then the article's title, then its own headings.

A last paragraph, so the end of the article sits well below the fold on most screens and the scroll has somewhere to go.
